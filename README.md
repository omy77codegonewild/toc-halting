# Problem 6: Turing Machine Simulation and Bounded Halting Prediction

A configurable Turing machine simulator plus an ML triage component that predicts whether a
`(machine, input)` pair **halts within a step limit L**. Simulation is always the ground truth:
the models only guess, and their guesses are compared with simulated outcomes at 7 step limits.

* **Live app:** [toc-halting.streamlit.app](https://toc-halting.streamlit.app) (free hosting, so the first load after a quiet spell can take about 30 s while it wakes up)
* **Report:** [REPORT.md](REPORT.md) (also as [REPORT.pdf](REPORT.pdf))
* **Viva preparation:** [VIVA_NOTES.md](VIVA_NOTES.md)
* **Every number in the report:** [results/summary.md](results/summary.md) (generated by `experiment.py`)

## Quickstart

Requires Python 3.10+.

**Linux / macOS**

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest tests -v       # 37 tests: simulator, features, models, headless app
.venv/bin/python experiment.py            # regenerate results/ (about 3 min on a 12-core CPU)
.venv/bin/streamlit run app.py            # interactive simulator & predictor
```

**Windows**

```bat
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python -m pytest tests -v
.venv\Scripts\python experiment.py
.venv\Scripts\streamlit run app.py
```

Pre-computed datasets, trained models and plots are included in `results/`, so the app and the
tests work immediately without running the experiment. `python experiment.py --quick` runs a
smaller smoke test, but note that it **overwrites** `results/` with less reliable numbers. Run the
full version afterwards.

## Files

| File | What it does |
|---|---|
| `tm.py` | Simulator: sparse two-way tape, `L`/`R`/`S` moves, configurable states, symbols, blank and start state; exact and Zobrist-hash loop detection; rule parser with error messages; Graphviz state diagram; 11 example machines (busy beavers, incrementer, unary adder, palindrome checker, countdown, non-halters); random machine generators |
| `features.py` | 19 static features (transition table, state-graph reachability, input statistics) and 8 probe features (behaviour during a 10-step trial run) |
| `ml_models.py` | Decision Tree, Random Forest and `BalancedMLP` (neural net with a decision threshold tuned on a validation split for class imbalance) |
| `experiment.py` | Builds the datasets, then runs a 5-seed evaluation at 7 step limits plus studies of machine size, feature importance, probe length, the MLP imbalance fix, hand-written machines and cost; writes plots, CSVs, `models.joblib` and `summary.md` to `results/` |
| `app.py` | Streamlit app with 5 tabs: overview (where each requirement is shown), step-through simulator (tape view, rule applied at each step, transition table, state diagram, execution trace), 3-model predictor vs simulation at every L with explained features and a batch tester, experiments (dataset, step limit, machine size, features, robustness, cost), theory notes |
| `tests/` | Simulator semantics (incrementer outputs, busy beavers, loop vs limit, parser errors, missing rules), features, models, headless app tests |
| `REPORT.md` / `REPORT.pdf` | Experimental report: background, method, results, discussion, conclusion |
| `VIVA_NOTES.md` | Plain-language notes and likely examiner questions |

## Key design point: three outcomes, not two

The simulator never answers just "halts / doesn't halt":

1. **halted**: reached the halt state `H` (or there was no rule for the current state and symbol).
2. **looping**: the full configuration `(state, head, tape)` repeated, which **proves** it never halts.
3. **limit**: budget exhausted. This means *unknown*, never "does not halt".

The ML label is "halts within L steps" (`1`) vs "has not halted within L steps" (`0`). Class `0`
deliberately does **not** mean "never halts", so the system never claims to solve the general
halting problem, which is undecidable.

## Headline results (mean ± std over 5 splits, L = 250)

| | Random machines | Hard machines (unresolved after 10 steps) |
|---|---|---|
| Simulate 10 steps (baseline) | accuracy 0.978 ± 0.004 | F1 0.000 (finds none of the slow halters) |
| Random Forest, static features only | accuracy 0.811 ± 0.005 | F1 0.399 ± 0.015 |
| Random Forest, static + 10-step probe | accuracy 0.978 ± 0.004 | F1 0.527 ± 0.008, recall 0.843, ROC-AUC 0.940 |

ML adds nothing where a short simulation already decides; it becomes a useful triage filter on
the machines a short simulation cannot resolve. See the report for the step-limit, machine-size,
probe-length and out-of-distribution analyses.

## Machine text format

One rule per line: `state read write move next`, e.g. `q0 1 0 R q1`. Moves are `L`, `R`, `S`;
the halt state is `H`; a missing rule also halts the machine; `#` starts a comment. Any single
characters can be tape symbols, and the blank symbol and start state are configurable in the app.
